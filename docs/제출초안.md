# PART 1. 서비스 기획서

## 1. 서비스 한 줄 소개

**채무회복 내비게이터**는 공식 신용정보조회서에서 흩어진 채무정보를 AI가 하나의
채무 지도로 구조화하고, 상환 판단에 필요한데 문서에 없는 정보를 찾아 보완한 뒤,
**상환여력은 확정 숫자로, 제도는 검토 후보로** 제시하여 사용자가 공식 상담까지
도달하도록 돕는 웹서비스다.

본 서비스는 채무조정 제도의 신청 가능 여부를 확정적으로 판정하지 않는다. 대신
사용자가 자신의 상황을 정확히 이해하고, 적합 가능성이 있는 제도를 근거와 함께
비교한 뒤 공식 상담과 신청을 완료할 수 있도록 돕는 **채무회복 실행 코파일럿**을
지향한다.

> ### 핵심 원칙: 숫자는 확정, 제도는 후보
>
> **확정적으로 제시하는 것** — 총 채무액, 월 상환 부담, 필수생활비 반영 후 월
> 가용재원, 월 부족액. 이 값들은 사용자가 확인한 입력에 대한 결정론적 계산
> 결과이므로 명확한 숫자로 제시한다.
>
> **후보로만 제시하는 것** — 채무조정 제도의 적합성, 신청 가능 여부, 감면 범위,
> 심사 결과. 이 값들은 공식기관의 심사 영역이므로 검토 후보와 근거, 미확인 조건만
> 제시한다.

이 원칙이 본 서비스의 유용성과 안전성을 동시에 담보한다. 사용자는 **자신이
몰랐던 사실 하나를 확실하게** 얻고, **제도 판단은 공식기관에** 맡기게 된다.

> **AI가 읽고, 코드가 계산하고, 공식기관이 판정한다.** — 3단 책임 분리가 본
> 서비스 아키텍처의 요약이다 (6장 참고).

## 2. 문제 정의

### 2.1 기존 문제 인식의 수정

신용회복위원회는 이미 무담보·담보채무, 연체 상태, 재산, 소득, 부양가족, 소득증빙
가능 여부 등을 입력해 적합한 채무조정 제도를 확인할 수 있는 간편진단 서비스를
제공하고 있다. 따라서 "무료·비대면 자가진단 도구가 존재하지 않는다"는 문제
정의만으로는 기존 공공서비스와의 차별성을 확보하기 어렵다.

본 프로젝트는 문제를 다음과 같이 재정의한다.

> **저신용·다중채무자는 제도 이름을 확인한 이후에도 여러 금융회사의 채무정보를
> 하나로 정리하고, 자신의 상환여력을 계산하며, 결과의 불확실성을 이해하고, 상담에
> 필요한 정보를 준비해 실제 신청 행동으로 옮기는 데 어려움을 겪을 수 있다.**

신용회복위원회의 채무조정도 상담·접수, 채권금융회사 통지, 채권 신고, 채무조정안
심사와 동의, 합의서 체결, 변제계획 이행 등 여러 단계로 진행된다. 즉, 자가진단
결과를 확인하는 것과 실제 채무회복 절차를 시작·완료하는 것은 서로 다른 과제다.

### 2.2 공식 문서에 존재하는 구조적 공백

본 서비스가 해결하는 문제는 추상적 불편이 아니라 **공식 문서 자체의 구조적
공백**이다.

한국신용정보원이 운영하는 크레딧포유(본인신용정보 열람서비스)에서 누구나
**무료로** 「신용정보조회서」를 PDF로 발급받을 수 있다. 이 문서에는 전 금융권의
대출 내역, 신용카드 정보, 연체 기록, 보증 내역, 공공기록이 담긴다.

그러나 이 문서만으로는 **자신이 그 채무를 감당할 수 있는지 알 수 없다.** 상환
부담 계산에 필요한 다음 정보가 조회서에 담기지 않거나 불완전하기 때문이다.

| 조회서로 알 수 있는 것 | 조회서로 알 수 없는 것 |
|---|---|
| 어느 금융회사에 채무가 있는가 | 각 채무의 적용 금리는 얼마인가 |
| 채무 종류와 금액은 얼마인가 | 매달 실제로 나가는 상환액은 얼마인가 |
| 연체가 있는가 | 필수생활비를 쓰고 나면 얼마가 남는가 |
| 보증·공공기록이 있는가 | 지금 구조를 유지하면 매달 얼마가 부족한가 |

> **문제의 핵심:** 공식 문서 한 장으로 **내 채무 구조**는 알 수 있다. 그러나
> **내가 감당할 수 있는지**는 그 문서로 알 수 없다.

본 서비스는 이 공백을 메운다. 조회서를 구조화하고, 빠진 항목이 무엇인지
사용자에게 알려주며, 보완된 정보로 상환여력을 계산한다.

### 2.3 해결하고자 하는 실행 단절

- 대출이 여러 금융회사에 분산돼 있어 전체 채무구조를 파악하기 어렵다.
- 공식 조회서를 발급받아도 금리와 월 상환액이 없어 상환 부담을 계산할 수 없다.
- 어떤 정보가 제도 검토에 중요하고, 어떤 정보가 빠져 있는지 알기 어렵다.
- 결과가 특정 제도의 '확정 자격'을 의미하는지, 단순한 검토 후보인지 구분하기
  어렵다.
- 상담 전 준비할 서류와 금융기관에 확인할 질문을 알기 어렵다.
- 제도별 설명은 찾을 수 있지만 자신의 현금흐름을 기준으로 어떤 행동을 먼저 해야
  하는지는 알기 어렵다.
- 채무 문제와 함께 실직, 폐업, 주거 불안, 복지 공백이 발생해도 어느 기관에 함께
  도움을 요청해야 하는지 알기 어렵다.

### 2.4 검증해야 할 핵심 가설

1. **정보 정리 가설** — AI가 신용정보조회서에서 핵심 정보를 자동 추출하면
   사용자의 채무정보 정리 시간과 입력 누락을 줄일 수 있다.
2. **이해도 가설** — 상환여력을 확정 숫자로 제시하고 제도는 충족 조건·미확인
   조건·공식 근거와 함께 후보로 표시하면, 사용자가 결과의 의미와 한계를 더
   정확히 이해할 수 있다.
3. **실행 전환 가설** — 상담 준비서류, 질문 목록, 기관별 연락 경로와 7일
   행동계획을 제공하면 단순 정보 조회보다 실제 상담 행동으로 이어질 가능성을
   높일 수 있다.

## 3. 목표 사용자와 서비스 채널

### 3.1 MVP 핵심 사용자

- 2개 이상의 금융회사에 채무를 보유한 사람
- 연체 전이거나 연체일수가 89일 이하인 사람
- 근로소득 또는 사업소득 등 계속적·반복적인 소득이 있으나 월 상환 부담이 커진
  사람
- 자신의 전체 채무액과 월 상환 부담을 정확히 파악하기 어려운 사람
- 채무조정 상담을 받아야 할지 고민하고 있지만 아직 상담을 시작하지 않은 사람

초기 타깃을 연체 전 또는 단기연체 금융소비자로 한정함으로써, 문제가 장기화하기
전에 상담과 예방적 채무조정을 검토하도록 돕는다.

### 3.2 MVP에서 별도 상담으로 연결할 사용자

- 연체일수가 90일 이상인 경우
- 소득활동이 어렵거나 월 상환여력이 사실상 없는 경우
- 개인회생·개인파산 절차가 이미 진행 중인 경우
- 보증채무, 조세채무, 사인 간 채무 등 복잡한 채무가 포함된 경우
- 담보채무 또는 재산관계가 복잡한 경우
- 법적 분쟁, 강제집행, 압류 등이 진행 중인 경우
- 입력 내용에 중대한 모순이 있거나 분석 신뢰도가 낮은 경우

### 3.3 서비스 채널

- **1차 채널:** 모바일 중심 반응형 웹서비스
- **보조 채널:** PC 웹
- **상담 연계:** 분석 결과를 PDF 또는 공유용 요약화면으로 생성해 신용회복위원회,
  금융회사, 지자체 및 관련 상담기관 방문 시 활용
- **접근성:** 핵심 용어 설명, 큰 글씨, 쉬운 말 모드, 단계별 입력, 입력 중단 후
  재개 기능

## 4. 솔루션 개요

### 1단계. 채무정보 입력

| 순위 | 입력 방식 | 비고 |
|---|---|---|
| 1 | **크레딧포유 「신용정보조회서」 PDF 업로드** | 한국신용정보원, 온라인 무료 발급 |
| 2 | 금융회사별 부채증명서 업로드 | 채권자별 개별 발급 |
| 3 | 금융회사별 채무 직접 입력 | 문서 발급이 어려운 사용자용 |
| 4 | 데모용 합성 조회서 선택 | 공모전 시연 및 사용자 테스트용 |

### 2단계. AI 채무정보 구조화

**조회서에서 직접 추출**: 금융회사명, 채무 유형, 현재 잔액, 실행일·만기일,
연체 발생 여부와 연체일수, 담보·무담보 여부, 보증·공공기록.

**보완이 필요한 항목**: 적용 금리, 월 예정 상환액, 상환 방식 — 조회서에 없거나
불완전하기 때문이다. 추출한 정보는 사용자가 반드시 확인·수정하도록 한다.

### 3단계. 누락정보 확인

고정 5문항(월 실수령소득, 월 필수생활비, 소득증빙 가능 여부, 부양가족, 최근
6개월 신규채무) + 조건부 최대 3문항(담보자산, 추심 연락, 실직·휴업·폐업).

### 4단계. 채무 지도와 현금흐름 분석

**채무 지도**: 총 채무액, 금융회사별 비중, 담보·무담보 비중, 평균·최고 금리,
연체 채무, 최근 발생 채무.

**현금흐름 (확정 숫자)**: 월 총 예정 상환액, 월 가용재원, 월 부족액, 소득 대비
상환 부담률.

### 5단계. 회복경로 비교 (최대 3개)

신속채무조정 / 사전채무조정 / 채권금융회사 상환조건 변경 문의 / 개인워크아웃 /
법원 개인회생·파산 상담 / 고용·복지·법률 복합지원 상담 — 신용회복위원회 공식
기준상 신속채무조정 30일 이하, 사전채무조정 31~89일, 개인워크아웃 90일 이상.

### 6단계. 7일 실행계획 생성

오늘(연체·자동이체 확인) → 1일 이내(서류 준비) → 2일 이내(상담 예약) → 상담 전
확인사항 → 금융회사 문의 질문 → 상담 후 계획 업데이트.

## 5. MVP 구현 범위

### 5.1 1등급 — 반드시 완성 (구현 완료 ✅)

문서 기반 채무정보 추출 / 사용자 확인·수정 / 누락정보 탐지·보완 입력 / 현금흐름
확정 계산 / 회복경로 비교(최대 3개) / 불확실성 표시(3-state) / 7일 행동계획 /
**상담용 요약서 PDF** / 안전 응답 필터.

### 5.2 2등급 — 축소 구현 (구현 완료 ✅)

채무 지도 시각화 2종 차트 / 고정 질문 방식 / 소득 20% 감소 단일 시나리오 / 사전
구축 정책 카드 인용 / 규칙 기반 복합지원 신호 탐지.

### 5.3 3등급 — MVP 제외

실제 채무조정 신청 대행, 금융회사 계정 로그인·자동 계좌조회, 마이데이터
실연동, 채권자 자동 협상, 개인회생 변제계획 확정 계산, 채무감면액 보장, 투자·
대출상품 추천, **사용자 신용평가 또는 신용점수 예측**.

> 신용점수 예측을 명시적으로 제외하는 이유: 신용평가사의 점수 산정 로직은
> 비공개이므로 예측값을 검증할 수 없다. 검증할 수 없는 수치는 제시하지 않는다.

### 5.4 구현 화면 (7개, 전부 구현 완료)

1. 서비스 소개·유의사항·개인정보 처리 동의
2. 신용정보조회서 발급 안내 및 문서 업로드 (4가지 입력 방식 전부 동작)
3. AI 추출 결과 확인·수정
4. 누락정보 보완 입력
5. 채무 지도 및 현금흐름 결과
6. 회복경로 비교 및 근거 상세
7. 7일 행동계획 및 상담용 요약서

## 6. AI가 필요한 이유

### 6.1 AI가 담당하는 업무

- **비정형 금융문서 이해**: 발급기관·상품마다 다른 표현("대출잔액/채무잔액/
  원금잔액/미상환원금")을 같은 필드로 표준화한다.
- **누락 및 모순 탐지**: 잔액 합계 불일치, 연체일수 상충, 금리 없이 월상환액만
  있는 경우, 실행일 부재로 신규채무 여부 판단 불가 등을 찾아 사용자에게
  확인시킨다.
- **근거 기반 개인화 설명**: 연체일수가 중요한 사용자에게는 연체구간 중심,
  담보채무가 있는 사용자에게는 담보채무 검토 필요성을 우선 설명한다.
- **실행계획 생성**: 긴급도(연체 임박, 소득증빙 부족, 채무 목록 불완전, 실직·
  폐업 확인)에 따라 다음 행동 우선순위를 조정한다.

### 6.2 AI가 담당하지 않는 업무

제도 조건의 최종 충족 여부 확정, 법률적 자격 판정, 자동 신청·계좌 조작, 사용자의
상환중단 결정, 금융기관과의 협상 결과 예측, 실제 납입액 산정 — 이 업무는
생성형 AI가 단독으로 수행하지 않는다.

제도 후보 선별은 **버전 관리되는 규칙 엔진**, 금액 계산은 **결정론적 계산
모듈**, 최종 판단은 **공식 상담기관 또는 법원**이 담당한다. 생성형 AI는 문서
이해와 설명 생성 계층에만 관여한다.

#### 6.2.1 이 설계는 선택이 아니라 규제 요건이다

> **적용 범위를 정확히 적는다.** 본 서비스는 개인신용평가를 수행하지 않으므로
> 아래 두 규범의 **직접 적용 대상이 아니다.** 그럼에도 규범이 요구하는 수준을
> 구조적으로 충족하며, **인접 영역이라 확장 시 즉시 해당된다.**

| 근거 | 요구 내용 | 본 서비스의 대응 |
|---|---|---|
| AI 기본법 (2026-01-22 시행) | 고영향 AI의 설명가능성·편향성 테스트 의무. 신용평가는 고영향 AI 대표 사례로 명시됨 | 제도 후보 선별을 규칙 엔진이 전담해 "왜 이 결과인가"가 조건 단위로 100% 설명됨 |
| 신용정보법 제36조의2 (자동화평가 대응권) | 자동화 평가에 대한 설명 요구·이의제기·재산출 요구권 | `/api/session/{id}/explain` 이 판정 근거·입력값·규칙 버전·정책 기준일을 항상 재현 |
| 금융분야 AI 가이드라인(금융위) | 소비자 대응권 보장 | 동일 |

> **시행일 확인 근거(2026-09-06 재검증)**: 법률 제20676호(2025-01-21 공포, 공포 후
> 1년 경과 시행)에 따라 **2026-01-22 시행**이 맞다 — 국가법령정보센터 시행령
> 페이지에도 `efYd=20260122`로 명시되어 있다. 별도로 2025-12-30 국회를 통과한
> **개정안**이 2026-07-21 시행 예정인데, 이는 원 조문이 아닌 개정 조항의
> 시행일이므로 위 날짜와 모순되지 않는다. 고영향 AI 분류·설명가능성 의무가
> 원 조문/개정 조항 중 어디에 속하는지는 제출 전 국가법령정보센터 조문
> 대조로 재확인한다.

만약 LLM이 채무조정 제도의 적합성을 직접 판정한다면, "주요 기준" 설명이
원리적으로 불가능해진다 — LLM의 판단 근거는 사후에 재현되지 않기 때문이다.

### 6.3 전체 처리 구조

```text
신용정보조회서·사용자 입력
        ↓
개인정보 탐지 및 마스킹
        ↓
AI 문서 정보 추출 (LLM/VLM)
        ↓
사용자 확인·수정                    ← 인간 감독 지점 1
        ↓
누락·모순 정보 탐지 및 보완 입력
        ↓
결정론적 현금흐름 계산 모듈          ← 확정 숫자 산출
        ↓
공식 조건 기반 규칙 엔진 (버전 관리)  ← 제도 후보 선별
        ↓
정책 카드 인용 및 근거 연결
        ↓
AI 개인화 설명·행동계획 생성 (LLM)
        ↓
안전성 필터 및 금지 표현 점검
        ↓
회복경로 비교·상담용 요약서 제공     ← 인간 감독 지점 2 (공식 상담 연계)
```

### 6.4 AI 제거 시 사라지는 핵심 가치

형식이 다른 공식 문서를 하나의 채무 목록으로 통합하는 것, 모순·누락 정보를
찾는 것, 사용자별로 중요한 조건을 선별해 설명하는 것, 공식 근거를 사용자
언어 수준으로 변환하는 것, 상담 질문·행동계획을 개인화하는 것 — 이 모두가
AI 없이는 사용자가 직접 수행해야 한다.

## 7. 회복경로 선별 방식

### 7.1 판정이 아닌 후보 선별

"신청 가능합니다", "이 제도가 가장 유리합니다" 같은 확정 표현은 쓰지 않는다.
대신 "현재 입력 기준 우선 검토할 수 있는 경로입니다", "최종 자격과 지원 내용은
공식 상담을 통해 확인해야 합니다"로 표현한다. 단, 현금흐름 계산 결과는 확정
표현을 사용한다 — 사용자가 확인한 입력에 대한 결정론적 산출값이며 제도 심사와
무관하기 때문이다.

### 7.2 결과 카드 구성 (11개 항목)

경로명 · 검토 우선순위 · 담당 기관 · 충족 조건 · 미확인 조건 · 결과를 바꿀 수
있는 요소 · 판단 근거(사용자 입력) · 공식 정책 근거와 기준일 · 다음 행동 ·
상담 시 준비할 질문 · 최종 확인이 필요한 이유.

### 7.3 판정 불가 상태

핵심 입력정보 부족, 문서 간 정보 충돌, 제도 기준 미확인, 서비스가 다루지 않는
복잡한 채무 포함 시 억지로 추천하지 않고 '판단 불가'를 제공한다. **판정 불가
상태에서도 현금흐름 계산 결과는 제공한다** — 제도 판정이 불가능해도 자신의
상환 부담을 아는 것은 독립적 가치가 있기 때문이다.

## 8. 상환여력 분석 설계

### 8.1 예상 감면액이 아닌 상환여력 중심

MVP는 실제 채무조정 결과를 예측하지 않는다. 대신 사용자의 **현재 상환 부담과
지속 가능한 상환여력**을 확정 계산한다.

### 8.2 기본 계산 구조

```text
월 가용재원 = 월 실수령소득 + 정기 지원금 − 필수생활비 − 주거비 − 의료·돌봄비 − 기타 필수 고정비
월 부족액   = 현재 월 예정 상환액 − 월 가용재원
소득 대비 상환 부담률 = 현재 월 예정 상환액 ÷ 월 실수령소득 × 100
```

### 8.3 결과 표현 방식 (예시)

> **김하늘 님의 현재 상환 구조**
>
> | 항목 | 금액 |
> |---|---|
> | 월 실수령소득 | 250만 원 |
> | 필수생활비 및 주거비 | 145만 원 |
> | **월 가용재원** | **105만 원** |
> | 현재 월 예정 상환액 | 118만 원 |
> | **월 부족액** | **13만 원** |
> | 소득 대비 상환 부담률 | 47.2% |
>
> **매달 13만 원이 부족합니다.** 이 계산은 입력하신 필수생활비 145만 원을
> 기준으로 합니다. 의료비나 부양가족 지출이 추가로 있다면 부족액은 더 커집니다.

### 8.4 시나리오 분석

MVP는 **소득 20% 감소** 단일 시나리오를 제공한다. 월 가용재원 105만 원 → 55만
원, 월 부족액 13만 원 → 63만 원(약 4.8배)으로 계산되는 방식이다.

## 9. 공식 근거 데이터 관리

### 9.1 데이터 출처

신용회복위원회, 금융위원회, 법원 및 사법부, 금융감독원, 한국신용정보원,
서민금융진흥원, 정부·지자체의 공식 복지·고용 지원 정보만 사용한다. 블로그,
광고성 상담사이트, 출처 불분명 커뮤니티 자료는 제도 판정 근거로 사용하지 않는다.

### 9.2 정책 카드 구조

제도명/담당기관/주요 대상, 검토 조건/제외·추가 확인 조건, 필요 입력정보/지원
내용/준비서류/신청 경로, 원문 출처/정책 기준일/마지막 검토일/변경 이력.

### 9.3 버전 관리

화면마다 정책 기준일을 표시하고, 제도 조건 변경 시 기존 규칙을 덮어쓰지 않고
새 버전을 생성한다. 기준일을 확인하지 못한 제도는 결과 생성을 중단하고 공식
상담을 안내한다.

## 10. 금융 AI 안전성·신뢰성 설계

### 10.0 준거 기준

금융보안원이 2026년 개발·발표한 「금융 AI 안전성·신뢰성 평가 프레임워크」(신뢰성
4개·안전성 6개 항목: 모델 성능·데이터 품질·공정성/편향성·설명가능성 및
AI 특화 보안위협·공격 탐지대응·자산 보호·외부 모델 검증·기존 보안관리 확장·
보안 검증운영)에 따라 자체 점검 결과를 정리한다. 정식 평가 운영은 시범검증을
거쳐 추후 시작될 예정이며, 발표·시범검증 등 세부 일정은 제출 전 금융보안원
공식 발표 자료로 재확인한다.

### 10.1 신뢰성 영역

1. **모델 성능 관리** — 문서 추출 정확도를 필드별로 측정(14장). 제도 조건과
   금액은 규칙 엔진·계산 모듈이 산출하며 LLM 출력에 의존하지 않는다.
2. **데이터 품질 관리** — 합성 신용정보조회서만 사용(실제 개인정보 미포함),
   누락·상충·경계값 사례 의도적 포함, 정책 카드는 공식 출처·기준일·변경이력 관리.
3. **공정성·편향성** — 소득·연령·채무규모에 따라 출력 구조가 달라지지 않도록
   고정. 낙인적 표현 금지 목록 사전 정의 후 출력 단계에서 점검. 특정 금융회사·
   상품을 유리하게 서술하지 않으며 상품 추천 기능 자체를 제외.
4. **설명가능성** — 사용자 입력, AI 추출값, 사용자 수정값, 규칙 엔진 조건과
   버전, 계산 모듈 산출값과 계산식, AI 생성 설명, 공식 근거와 기준일을 화면에서
   분리 표시. 모든 숫자는 추적 가능하다.

### 10.2 안전성 영역

5. **AI 특화 보안위협** — 업로드 문서의 프롬프트 인젝션 탐지·무력화, 추출
   텍스트는 지시문이 아닌 데이터로만 처리, 시스템 프롬프트·규칙 조건 노출 유도
   질의 차단, 의도적 연체·허위 신청·재산 은닉 요청 거부.
6. **AI 특화 공격 탐지·대응** — 탈옥 시도·역할 변경 요구 로깅 및 세션 단위
   차단, 금지 주제 반복 시 공식 상담 안내로 전환.
7. **AI 자산 보호관리** — 원본 문서는 세션 종료 후 TTL 자동 삭제, 개인정보
   업로드 즉시 마스킹, 프롬프트·정책 카드 접근 권한 분리.
8. **외부 모델·데이터 검증** — 외부 LLM 응답을 그대로 신뢰하지 않고 제도 조건·
   금액은 내부 규칙 엔진·계산 모듈로 재검증. 정책 근거는 사전 검증된 정책 카드
   에서만 인용.
9. **기존 보안관리 확장 적용** — 전송 구간 암호화, 접근 통제, 로그 마스킹.
10. **보안 검증 및 운영관리** — 배포 전 공격 테스트 케이스 전량 실행, 중대
    환각·위험 조언·개인정보 노출은 위험등급 분리 관리.

| 인젝션 스캐너 | 문서 삽입형·질의형 공격 전량 대응 |
| PII 마스킹 | 업로드 즉시 적용, 우회 경로 없음(데모 문서·직접 입력 포함) |
| 업로드 원본 TTL 자동 삭제 | 앱 lifespan에 스위퍼 배선 완료 |
| 숫자 그라운딩 검증 | 계산 결과에 없는 금액이 설명문에 등장하면 폐기. 중대 환각 0건 |
| 컨테이너 보안 | 비-root(`uid 1000`) 실행 |
| 경계 거리 안전장치 | 연체일수 안내에서 "도달 불가능한 방향" · "더 연체하면 유리해 보이는" 두 결함을 발견해 수정 완료(2026-09-03) |

**재현성**: 같은 입력을 반복 투입해도 규칙 엔진·계산 모듈은 항상 동일한 출력을
낸다(순수 함수, 난수·현재시각 미참조). LLM이 담당하는 추출·서술 영역만 반복 시
표현이 달라질 수 있으며, 이 변동성이 금액·자격 판정에 영향을 주지 않도록
격리한 것이 본 설계의 핵심이다.

### 10.4 환각 방지 원칙

제도 조건은 생성형 AI의 사전지식으로 답변하지 않는다. 공식 정책 카드에 존재하는
정보만 사용하고, 근거가 확인되지 않는 내용은 '확인 불가'로 표시한다. 제도 조건과
숫자는 규칙 엔진·계산 모듈에서 가져오며 LLM이 임의로 생성하지 않는다.

### 10.5 인간 감독

문서 추출값을 사용자가 확인하기 전에는 경로 분석을 실행하지 않는다. 신뢰도가
낮은 필드는 자동 경고한다. 고위험·복잡 사례는 공식 상담기관으로 연결한다. 최종
신청과 법률적 판단은 공식기관과 법원이 담당한다.

### 10.6 위험 행동 방지

의도적 연체 유도, 임의 상환중단 권고, 재산·소득·채무 허위 작성 안내, 신규 대출로
기존 채무 상환 단정적 권고, 추심 즉시 중단 확정, 제도 승인 보장 — 이런 안내는
하지 않는다.

### 11.1 공공기관이 직접 하면 되지 않는가

**첫째, 관할의 문제다.** 채권금융회사와의 상환조건 변경 협의, 법원 절차,
고용·복지 지원처럼 소관이 서로 다른 경로를 한 화면에서 비교하는 것은 특정
기관의 역할이라기보다 중립적 안내자의 역할에 가깝다.

**둘째, 목적지가 다르다.** 본 서비스의 성공 지표는 자체 이용자 수가 아니라
**공식 상담으로 얼마나 연결되었는가**이다. 상담용 요약서는 사용자가 공식기관에
가져가기 위한 산출물이다.

**셋째, 다루는 구간이 다르다.** 공공 자가진단은 '어떤 제도가 있는가'를 다루고,
본 서비스는 '내 문서를 어떻게 정리하고 무엇을 준비해 상담에 갈 것인가'를
다룬다.

따라서 본 서비스는 기존 공공 자가진단과 경쟁하는 서비스가 아니라, **진단과
공식 상담 사이의 실행 구간을 메우는 보완적 서비스**다.

**2단계**: 90일 이상 연체자·개인워크아웃 지원, 개인사업자·휴폐업자 지원 경로,

## 20. 유의사항 (기획서 파트 공통)

본 서비스는 금융·법률 자문, 신용평가 또는 공식 자격심사를 제공하지 않는다.
신용회복위원회 채무조정은 신용회복위원회의 공식 상담과 심사 절차를 따르며,
개인회생·개인파산은 관할 법원의 절차를 따른다.

서비스가 제공하는 상환여력 계산은 사용자가 입력하거나 확인한 정보에 대한
산술적 계산 결과이며, 회복경로와 행동계획은 해당 시점의 공식 공개자료를 바탕으로
한 상담 준비용 정보다. 최종 신청 가능 여부, 채무조정 조건, 감면 범위, 상환기간
및 법적 효과는 신용회복위원회, 법원 또는 해당 업무를 담당하는 공식기관을 통해
확인해야 한다.

서비스는 사용자가 특정 제도를 이용하기 위해 의도적으로 연체하거나, 허위정보를
제출하거나, 전문기관의 확인 없이 채무 상환을 중단하도록 권고하지 않는다.

### 1.3 처리 파이프라인

파일 종류 판별과 판독기 선택은 검증 단계(`ingest/uploader.py`) 한 곳에서만
확정한다. 그 결과(정규 MIME)를 라우터가 그대로 재사용해 PDF/이미지
판독기를 분기하므로, PNG/JPEG가 PDF 판독기(`pypdf`)로 잘못 전달되는 경로가
구조적으로 없다(2026-09-06 발견·수정, 12장 참고). PDF는 페이지별로 텍스트
레이어 유무를 판단해 자동으로 갈라진다 — 텍스트가 있으면 그대로 추출하고,
없거나 임계치(50자) 미만이면 페이지를 이미지로 렌더링한 뒤 이미지 업로드와
**동일한** Tesseract OCR 함수로 텍스트를 뽑는다.

```
업로드 → 검증(정규 MIME 확정) → 판독기 분기
   ├─ PDF: pypdf 텍스트 추출 (페이지별 임계치 미만이면 ↓)
   │        → 페이지 렌더링(150dpi·그레이스케일) → Tesseract OCR
   └─ 이미지(PNG/JPEG): Pillow 검증 → Tesseract OCR (동일 함수)
   → 인젝션 스캔(라인 제거) → PII 마스킹
   → LLM 추출 ─────────────────────────────── LLM 개입 지점 1
   → 사용자 확인 ────────────────────────── 인간 감독 지점 1 (INV-1 게이트)
   → 누락·모순 탐지 → 보완 질문 → 보완 입력
   → 현금흐름 계산 ───────────────────────── 확정 숫자 (항상 실행)
   → 트리아지 (REFER 시 규칙 엔진 생략)
   → 정책 카드 로드 → 3-state 조건 평가 → 경로 선별(최대 3)
   → 설명 생성 ─────────────────────────── LLM 개입 지점 2
   → 출력 필터 + 그라운딩 검증 → 실패 시 템플릿 대체
   → 7일 계획 → 상담용 요약서 PDF ──────── 인간 감독 지점 2 (공식 상담 연계)
```

`cashflow`는 항상 계산·반환된다. 정책 카드를 못 불러오거나 규칙 엔진이 실패해도
`undetermined=True`로 강등될 뿐 상환여력 결과는 그대로 제공한다.

## 4. 데이터 모델

### 4.1 출처 추적 — `Tracked[T]`

이 서비스의 모든 값은 **값과 출처를 함께** 들고 다닌다.

| 필드 | 의미 |
|---|---|
| `value: T \| None` | `None`이면 UNKNOWN이며 계산에서 제외된다 |
| `source` | `document` · `user_input` · `user_edit` · `derived` · `unknown` |
| `confidence` | `document`일 때만 의미(0.7 미만이면 화면 경고) |
| `page` / `raw_text` | 문서 근거 위치 / 원문 스니펫 |
| `user_confirmed` | INV-1 게이트 판정에 사용 |

금액(`Money`)은 float 거부, 원 단위 정수만 허용. 비율(`Ratio`)은 0~1 강제.
부담률용 `OpenRatio`는 상한 없음(100% 초과 상황이 핵심 대상이므로).

### 4.2 채무 — `Debt`

문서 추출: `creditor` `product_type` `balance` `executed_at` `maturity_at`
`overdue_days` `is_secured`. 보완 입력: `interest_rate` `monthly_payment`
`repayment_type` — 신용정보조회서에 없는 정보이므로 추출기가 이 값을 채워
반환하면 그 자체가 환각이다.

### 4.3 현금흐름 결과 — `CashflowResult`

`total_debt` `monthly_total_payment` `monthly_available` `monthly_shortfall`
(양수=부족) `dti_ratio` `max_overdue_days` `secured_ratio` `weighted_avg_rate`
`max_rate` `recent_debt_ratio` `trace`(계산 과정) `assumptions` `excluded_items`
`completeness`.

`secured_ratio`·`recent_debt_ratio`는 잔액·담보여부·실행일이 하나라도
미확인이면 `None`이다 — 부분 합계로 비율을 내면 "모른다"가 "충족"으로 둔갑하기
때문이다.

### 4.4 계산식

```
월 가용재원 = 월 실수령소득 + 정기 지원금 − 필수생활비 − 주거비 − 의료·돌봄비 − 기타 필수 고정비
월 부족액   = 현재 월 예정 상환액 − 월 가용재원          (양수 = 부족)
부담률      = 현재 월 예정 상환액 ÷ 월 실수령소득
신규채무비율 = Σ(기준일 − 182일 이후 실행 채무 잔액) ÷ 총 채무액
```

기준일은 `as_of` 인자로 주입한다(INV-6). 테스트는 `now`를 주입해 결과를
결정론적으로 재현한다.

### 4.5 경로 후보 — `PathCandidate`

경로명·우선순위·담당기관·충족조건·미확인조건·swing factor·근거·정책참조·다음
행동·상담질문·최종확인사유 11개 항목 (기획서 7.2와 1:1 대응).

## 5. 규칙 엔진

### 5.1 3-state 조건 평가

모든 조건은 `MET`·`NOT_MET`·`UNKNOWN` 중 하나로 평가된다. **`UNKNOWN`을
`NOT_MET`으로 취급하는 것은 금지한다** — "충족 못함"과 "확인 불가"는 사용자에게
완전히 다른 의미다. 필드가 사실 목록에 없거나 값이 `None`이면 연산자와 무관하게
`UNKNOWN`이다.

`eval()`·`exec()`를 쓰지 않는다 — 정책 카드는 데이터이므로 코드 실행 경로가
되어서는 안 된다. 지원 연산자: `between` `lte` `gte` `lt` `gt` `eq` `in`
`is_true` `is_false` `exists`.

### 5.2 정책 카드 6종

| ID | 제도 | 관할 | 연체 구간 | 검증 |
|---|---|---|---|---|
| `sinsok_debt_adjustment` | 신속채무조정 | 신용회복위원회 | 0–30일 | ✅ |
| `pre_debt_adjustment` | 사전채무조정 | 신용회복위원회 | 31–89일 | ✅ |
| `personal_workout` | 개인워크아웃 | 신용회복위원회 | 90일+ | ✅ (2026-09-02 검증 완료) |
| `creditor_negotiation` | 상환조건 변경 문의 | 각 채권금융회사 | 무관 | ✅ |
| `court_rehabilitation` | 개인회생·파산 상담 | 법원 | 무관 | ✅ |
| `complex_support` | 복합지원 상담 | 서민금융통합지원센터 등 | 무관 | ✅ |

신복위 제도 공통 조건: 총 채무액 15억 원 이하(무담보 5억·담보 10억), 최근 6개월
신규채무 원금이 총 채무원금의 30% 미만, 계속적·반복적 소득 존재.

신속채무조정 특례: 연체가 없어도 최근 6개월 내 실업·무급휴직·폐업, 90일 이상
입원, 개인신용평점 하위 10%(또는 하위 20%·연소득 4,500만원 이하) 등에 해당하면
신청 가능. 자가신고 항목이라 자동 판정하지 않고 상담 안내로 처리.

### 5.3 경로 선별과 정렬

```
사실 조립 → 카드별 3-state 평가 → 필수 조건 NOT_MET 이면 EXCLUDED
         → priority 순 정렬 → 상위 3개 반환
```

정렬 기준은 `priority`가 먼저, `status`는 동순위 안에서만 쓴다 — status를 먼저
정렬하면 조건 1개뿐인 보조 경로가 항상 `CANDIDATE`로 떠서, 조건이 많은 신복위
핵심 제도가 상위 3개 밖으로 밀려나는 결함이 있었다(발견·수정 완료).

### 5.4 판정 불가 / 트리아지

`max_overdue_days`·`total_debt` 미확인, 미해소 상충 정보 존재, 사용 가능한
정책 카드 0개 시 `undetermined=True`. **판정 불가여도 현금흐름 결과는
제공한다.** 트리아지에서 `REFER` 판정이면 규칙 엔진을 생략하되 현금흐름 섹션은
그대로 남긴다.

### 출력 필터

| 카테고리 | 적용 섹션 | 예 |
|---|---|---|
| `confirmatory` | **경로·계획만** | "신청 가능합니다" · "가장 유리" · "반드시 승인" |
| `stigmatizing` | 전체 | "무책임" · "빚더미" · "신용불량자" |
| `risky_advice` | 전체 | 의도적 연체 · 재산 은닉 · 허위 신고 · 임의 상환 중단 |
| `privacy_request` | 전체 | 다른 이용자 정보 요구 |

`confirmatory`를 경로 섹션에만 적용하는 이유: 현금흐름 섹션의 확정 표현은
허용되어야 한다("매달 13만 원이 부족합니다"는 확정 계산 결과이므로 단정해도
된다). 제도 적합성에 대해서만 단정을 막는다 — "숫자는 확정, 제도는 후보"
원칙의 구현이다.

필터에 걸린 문장은 폐기하고 결정론적 템플릿 문장으로 대체한다. 검증되지 않은
LLM 출력이 화면에 도달하는 경로는 없다.

### PII 마스킹 / TTL

적용 순서: 주민등록번호 → 카드번호 → 전화번호 → 계좌번호 → 이메일 → 주소.
금융회사명·금액·날짜는 마스킹하지 않는다(과잉 마스킹은 추출 성능을 떨어뜨림).
세션 만료 시 `upload_dir/{session_id}/`를 통째로 삭제하고 세션 레코드도
지운다.
