## Render 배포 절차

카드 등록이 필요 없다. `plan: free` 로 서비스가 생성되는 것을 실측 확인했다.
저장소가 공개라 GitHub App 연동 없이 저장소 URL 만으로 붙는다.

1. https://render.com 가입 (GitHub 로그인)
2. **New → Blueprint** → 이 저장소 선택 → `render.yaml` 자동 인식
3. `DN_OPENAI_API_KEY` 만 대시보드에서 입력 (`sync: false` 라 저장소에 없다)
4. 배포 후 `https://<서비스명>.onrender.com/healthz` 가 200 인지 확인

API 로 만들 수도 있다 — `POST /v1/services` 에 `serviceDetails.env="docker"`,
`plan="free"`, `envSpecificDetails.dockerfilePath="./Dockerfile"` 을 넣는다.

### 무료 플랜의 함정과 대응

무료 웹서비스는 **15분간 요청이 없으면 잠들고**, 다음 요청에서 30~60초 걸려
깨어난다. 심사위원이 URL 을 열었을 때 1분을 기다리는 상황은 피해야 한다.

### ⚠️ GitHub Actions 방식은 실측에서 동작하지 않았다

`.github/workflows/keepalive.yml` 이 10분마다 `/healthz` 를 호출하도록 만들었으나,
**`main` 병합 후 4시간 동안 예약 실행이 0회였다**(2026-09-03 05:58 병합 → 10:00 확인).

- 워크플로 상태: `active`
- 저장소 기본 브랜치: `main` (예약 실행 조건 충족)
- 수동 실행(`workflow_dispatch`): 정상 — `healthz -> 200`
- **`schedule` 이벤트 실행: 0회**

설정 문제가 아니다. GitHub 예약 실행은 지연·누락이 잦고 정확한 주기를 보장하지
않는다. **URL 접근 불가가 결격 사유인 상황에서 여기에 의존하면 안 된다.**
워크플로는 보조 수단으로 남겨 두되, 아래 중 하나를 주 수단으로 둔다.

### 채택: 외부 핑 서비스 이중화

무료이면서 목적에 맞게 만들어진 도구를 쓴다. **두 곳에 등록해 한쪽이 멈춰도
남도록** 한다 — 결격이 걸린 사안이라 단일 실패점을 두지 않는다.

대상 URL은 **`/healthz`** 로 고정한다. 이유가 두 가지다.

- LLM 을 호출하지 않아 무료 티어 한도(Groq 일 1,000 요청)를 소모하지 않는다.
- `config.yaml: ratelimit` 의 IP 당 호출 제한 대상이 아니다(제한은 문서 업로드·
  분석 두 엔드포인트에만 걸린다). 핑이 스스로 차단당하는 일이 없다.

#### 1. UptimeRobot

1. https://uptimerobot.com 가입
2. **+ New monitor**
   - Monitor type: `HTTP(s)`
   - Friendly name: `debt-recovery-navigator`
   - URL: `https://debt-recovery-navigator.onrender.com/healthz`
   - Monitoring interval: **5 minutes** (무료 최소값)
3. 저장 후 상태가 `Up` 으로 바뀌는지 확인

#### 2. cron-job.org

1. https://cron-job.org 가입
2. **CREATE CRONJOB**
   - Title: `dn-keepalive`
   - URL: `https://debt-recovery-navigator.onrender.com/healthz`
   - Schedule: **Every 10 minutes** (`*/10`)
3. 저장 후 **TEST RUN** 으로 200 이 오는지 확인

#### 무료 한도 안에 들어가는가

들어간다. Render 무료 웹서비스는 월 **750시간**을 주고 한 달 상시 가동이
**744시간**이다. 핑을 두 곳에서 보내도 인스턴스 가동 시간은 하나이므로 요청
수와 무관하게 744시간이다.

#### 확인

등록 후 **15분 이상 아무도 접속하지 않은 상태**에서 URL 을 열어 즉시 뜨는지 본다.
1초 안쪽이면 성공, 20초 넘게 걸리면 핑이 동작하지 않는 것이다.

```bash
curl -sS -o /dev/null -w "%{time_total}s\n" \
  https://debt-recovery-navigator.onrender.com/healthz
```

실측 기준: 잠든 상태 첫 요청 **22.6초**, 깨어 있을 때 **0.33초**.

> `.github/workflows/keepalive.yml` 은 지우지 않고 보조로 남겨 둔다. 지금은 예약
> 실행이 돌지 않지만 GitHub 쪽에서 뒤늦게 동작하기 시작해도 해가 없다(핑이
> 겹칠 뿐이다).

#### 심사가 끝나면

세 곳 모두 정리한다 — UptimeRobot 모니터 삭제, cron-job.org 작업 삭제,
GitHub Actions 탭에서 Keepalive 비활성화.

### 대안 (참고)

**Render Starter $7/월** 은 아예 잠들지 않아 핑이 필요 없다. 외부 서비스 두 곳을
관리하는 것보다 단순하다는 장점이 있으므로, 운영을 이어갈 계획이면 고려할 만하다.

## Hugging Face Spaces — 무료로는 불가

Docker SDK Space 는 **PRO 구독($9/월)이 있어야** 무료 CPU 에서 돌릴 수 있다.
무료 계정에서 `create_repo(space_sdk="docker")` 는 `402 Payment Required` 로 막힌다
(2026-09-02 실측). 무료로 제공되는 것은 정적 Space 뿐이라 이 서비스에는 맞지 않는다.

PRO 를 쓴다면 `scripts/deploy_hf_space.sh` 가 그대로 동작한다 — Space 저장소는
소스의 정본이 아니라 배포 산출물로 취급하고, 런타임에 필요한 것만 복사해 올린다.

## LLM 무료 티어 한도와 그 영향

Groq 무료 티어 실측 (2026-09-02, `qwen/qwen3.8-27b`):

- **8,000 TPM** — 요청마다 `max_tokens` 를 미리 예약하므로 추출 1건이 약 1,600 을
  먹는다(입력 ~600 + 예약 1,024). 분당 약 5회.
- **1,000 requests/day** — 한 세션이 LLM 을 최대 5회 부르므로 **하루 약 200세션**.

심사 규모에는 충분하지만 여유가 크지는 않다. 그래서 두 가지를 넣어 뒀다:

- `config/config.yaml: ratelimit` — IP 당 시간당 40회. 스크립트 남용이 하루 한도를
  태우는 것을 막는다. "문서 없이 직접 입력"은 LLM 을 안 쓰므로 제한하지 않는다.
- LLM 실패 시 **503 + 안내** — 한도 초과·장애에도 500 으로 죽지 않고 다른 입력
  방식으로 넘어가도록 안내한다. 화면은 계속 살아 있어야 결격을 피한다.

평가 하네스는 `eval/config.yaml: llm_call_interval_sec` 로 호출 간격을 둔다
(무료 티어 기준 13초). 유료 백엔드나 로컬 모델에서는 0 으로 둔다.
