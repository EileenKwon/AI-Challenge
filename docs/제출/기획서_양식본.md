## 2. 아이디어 기획 핵심내용(요약)

```
• 문제: 신용정보조회서와 공공 자가진단이 있어도, 여러 금융회사 채무를 한곳에 정리하고 실제
  상환여력을 계산해 상담 준비까지 이어가는 과정은 여전히 이용자가 직접 수행해야 한다.
• 해결: 금융문서의 핵심 채무정보를 AI가 구조화하고 사용자가 확인한 뒤, 문서에 없는 금리·월
  상환액·소득·필수생활비를 보완해 월 가용재원·부족액·상환부담률을 결정론적으로 계산한다.
• 판단: 채무조정 제도는 공식 공개기준을 반영한 정책 카드와 3-state(충족/미충족/미확인) 규칙
  엔진으로 검토 후보만 제시하며, 신청 가능 여부나 감면 결과를 확정하지 않는다.
• 실행: 결과 확인에서 끝내지 않고 준비자료, 상담 질문, 7일 행동계획, 상담용 요약서 PDF를
  제공해 신용회복위원회 등 공식 상담으로 이어지도록 지원한다.
• 구현·검증: 현재 배포 MVP는 문서·이미지·데모·직접입력 4개 경로와 8개 화면 흐름을 구현했으며,
  문서 추출과 계산·경로 검증을 분리해 재현 가능하게 구성했다.
• 핵심 원칙은 "AI가 읽고, 코드가 계산하고, 공식기관이 판정한다"이다.

```

## 3. 문제 정의 및 제안 배경

```
신용회복위원회에는 이미 채무조정 간편진단과 공식 상담이 존재한다. 따라서 본 서비스의 문제
정의는 "제도를 찾기 어렵다"가 아니다. 여러 금융회사에 흩어진 채무를 정리하고, 현재 현금흐름을
계산하고, 미확인 조건을 확인해 상담 준비까지 이어가는 실행 과정이 이용자에게 남아 있다는 점에
초점을 둔다.

신용정보조회서는 채무 현황을 파악하는 출발점이지만 실제 상환 부담을 계산하려면 적용 금리,
월 예정 상환액, 월 소득, 필수생활비 등 문서 밖의 정보가 추가로 필요하다. 본 서비스는 문서의
채무정보를 구조화하고 누락정보를 명시적으로 보완한 뒤, 사용자가 확인한 입력만으로 상환여력을
계산한다.

MVP 핵심 사용자는 2개 이상의 금융회사에 채무가 있고, 연체 전 또는 연체 89일 이하이며,
계속적·반복적인 소득이 있으나 월 상환 부담이 커진 금융소비자다. 장기연체 전에 현금흐름을
확인하고 예방적 상담을 검토하도록 돕는 데 우선 집중했다.

이 구간을 고른 이유는 선택지가 가장 많으면서 가장 빨리 닫히기 때문이다. 연체 30일을 넘기면
신속채무조정 구간을 벗어나고 90일을 넘기면 개인워크아웃 구간으로 이동한다. "지금 상담하면
달라지는" 구간인데, 정작 이 구간의 당사자는 무엇을 물어야 할지 몰라 상담을 미룬다.

1차 채널은 모바일 중심 반응형 웹이며 PC에서도 사용할 수 있다. 앱 설치·회원가입·본인인증을
요구하면 이 사용자층이 가장 먼저 이탈하므로 URL 접속만으로 끝까지 진행되도록 했고, 세션은
익명이며 TTL 만료 시 업로드 원본과 함께 자동 삭제된다.

연체 90일 이상, 개인회생·파산 진행, 복잡한 담보·재산관계, 법적 분쟁·압류 등은 자동 판정
범위를 넓히지 않고 공식 상담을 우선하도록 안내한다.

실서비스 시작 화면에는 "쉬운 말"·"글씨 크게" 접근성 기능과 정책 기준일이 표시되며, 진입
경로를 두 개로 나눠 제공한다 — [개인정보 없이 2분 데모 체험](합성 문서가 미리 선택된 상태로
시작)과 [내 문서로 시작]이다. 소개·동의 화면에서는 서비스 한계, 개인정보 처리, 문서 자동삭제
정책을 먼저 안내해 금융정보 입력 전에 이용자가 처리 범위를 확인하도록 했다.

```

## 4. 서비스 컨셉 및 차별성

```
① 문서 중심 입력: 사용자가 채무를 처음부터 모두 옮겨 적기보다 신용정보조회서 등에서 AI가
   핵심 채무정보를 구조화하고, 사용자는 추출값을 확인·수정한다.

② 숫자는 코드가 계산: 총 채무액, 월 가용재원, 월 부족액, 상환부담률은 LLM이 생성하지 않고
   결정론적 계산 모듈이 산출한다. 같은 입력과 기준일에는 같은 결과가 나온다.

③ 제도는 후보로 제시: 공식 출처·기준일을 관리하는 정책 카드와 3-state 규칙 엔진으로 충족·
   미충족·미확인을 구분한다. "신청 가능", "가장 유리" 같은 확정 판정을 하지 않는다.
   값이 확인되지 않으면 미확인으로 남기고 "모른다"를 "아니다"로 떨어뜨리지 않는다. 그 결과
   제도가 사라지지 않고 무엇을 확인하면 되는지가 남는다.

④ 상담 실행까지 연결: 준비자료·상담 질문·7일 행동계획·상담용 요약서까지 제공한다.

⑤ 기존 서비스와의 차이: 기존 간편진단은 이용자가 자신의 상황을 구조화해 입력하는 단계에서
   시작한다. 본 서비스는 그 이전 단계인 금융문서 읽기·채무정보 구조화부터 시작해, 문서 밖의
   현금흐름 정보를 보완하고 상담에 가져갈 실행 자료까지 만든다. 기존 공공 자가진단을 대체하지
   않고 공식 상담으로 넘어가는 구간을 보완한다.

⑥ 경계 근접도: 회복경로 화면의 [제외된 경로 보기]를 펼치면, 아직 해당되지 않는 제도까지 남은
   거리를 보여준다. 새 판정이 아니라 이미 나온 판정의 여유분을 조건표에서 되돌려 계산한 값이다.
   설계에서 가장 신경 쓴 지점은 안전이다. 연체일수는 가만히 있어도 늘기 때문에 새 구간 진입을
   기회처럼 제시하면 "기다렸다 연체를 더 쌓는 편이 유리하다"로 읽힌다. 이는 레드팀 케이스가
   차단하려는 바로 그 행동이므로, 이 방향의 문구에는 "의도적으로 연체하는 것을 권하지 않습니다"
   경고가 항상 붙고 강조 표시를 하지 않으며, 문구를 LLM이 아니라 코드가 생성한다. 되돌릴 수
   없는 방향(연체일수 감소)은 달성 불가능한 안내이므로 아예 표시하지 않는다.

```

## 5. 활용 데이터 및 생성형 AI 모델 적용 방안

```
• 입력 데이터: 크레딧포유 신용정보조회서, 금융회사별 부채증명서, 사용자가 직접 입력한 채무정보.
  공모전 시연·평가에는 실제 개인정보가 아닌 합성 신용정보조회서를 사용한다.
• 보완 데이터: 월 실수령소득, 필수생활비, 소득증빙 가능 여부, 부양가족, 계속소득 여부, 최근
  신규채무 여부, 채무별 금리·월 상환액 등 사용자가 확인·입력한 정보.
• 정책 데이터: 신용회복위원회·법원 등 공식기관 공개자료를 정책 카드로 관리하고 출처·정책
  기준일·변경 이력을 기록한다. 현재 정책 기준일은 2026-08-13이며 카드 6종 모두 공식 출처
  대조를 마쳤다.
• 검증 데이터: 합성 조회서 55건 이상, 제도 조건 조합 사례 100건 이상, 연체일수 경계값과
  레드팀 공격 사례 14건을 사용한다. 문서 추출 검증과 현금흐름·경로 검증은 서로 다른 테스트
  사례로 수행한다.
• 개인정보 보호: 업로드 직후 주민등록번호·카드번호·전화번호·계좌번호·이메일·주소 6종을
  마스킹한 뒤에만 외부 모델로 보낸다. 업로드 원본은 세션 TTL 만료 시 자동 삭제하며 문서를
  모델 학습에 사용하지 않는다.

배포환경에서는 Groq qwen/qwen3.8-27b를 사용한다. 생성형 AI는 비정형 금융문서에서 채무 필드를
추출·표준화하고, 계산·규칙 결과와 공식 근거를 바탕으로 사용자 설명, 상담 질문, 행동계획을
생성한다.

누락·모순 탐지, 금액 계산, 제도 조건 평가는 별도 코드 모듈이 수행한다. 제도 자격의 최종 확정,
신용점수 예측, 감면액·승인 가능성 예측은 AI에 맡기지 않는다. 문서 추출 텍스트는 LLM 전달 전에
개인정보를 마스킹하고, 설명문 숫자는 계산 결과와 대조해 근거 없는 숫자가 있으면 그 문장을
폐기하고 결정론적 템플릿으로 대체한다.

AI를 제거하면 금융회사·상품마다 표현과 형식이 다른 문서를 사용자가 직접 읽고 공통 항목으로
옮겨야 한다. 반대로 금액 계산과 제도 조건처럼 정답이 재현돼야 하는 영역까지 AI에 맡길 이유는
없다. 따라서 AI는 비정형 정보를 구조화하고 설명으로 변환하는 역할에 집중하고, 정답이 필요한
영역은 코드가 담당한다.

[이 역할 분담을 택한 규제상 이유]
신용정보법 제36조의2는 자동화평가의 결과·주요기준·기초정보에 대한 설명 요구와 이의제기를
보장한다. AI 기본법(2026-01-22 시행)은 여신심사·신용평가에 쓰이는 AI를 고영향으로 분류해
설명가능성과 편향 점검을 요구한다.

본 서비스는 개인신용평가를 수행하지 않으므로 두 규범의 직접 적용 대상이 아니다. 다만 요구
수준은 구조적으로 충족한다 — 제도 후보의 판정 근거가 정책 카드의 조건 한 줄 한 줄이고 공식
원문 인용과 기준일이 함께 보관되므로, "주요기준"을 사후에 재구성할 필요가 없다. LLM이 판정을
맡았다면 이 설명은 원리적으로 만들 수 없다. 인접 영역이라 확장 시 즉시 해당되며, 그때에도
아키텍처를 바꿀 필요가 없다는 점이 이 구조를 택한 이유 중 하나다.

```

## 6. 기대 효과 및 확장 가능성

```
금융소비자는 여러 금융회사에 흩어진 채무를 한 번에 정리하고, 사용자가 확인한 입력을 기준으로
월 가용재원·부족액과 상환부담률을 확인할 수 있다. 또한 빠진 정보를 미확인 상태로 구분해 잘못된
확정 판단을 피하고, 상담 전에 확인할 자료와 질문을 준비할 수 있다.

사용자는 반복적인 수기 정리 부담을 줄이고 상담 전에 자신의 현금흐름과 미확인 항목을 정리할 수
있다. 상담기관은 채무 목록·현금흐름·미확인 정보·질문이 구조화된 자료를 받을 수 있어 초기
사실관계 확인을 돕는 참고자료로 활용할 수 있다. 상담용 요약서에 포함할 항목은 이용자가 직접
선택하므로 동의 없이 정보가 전달되지 않는다.

실제 상담시간 단축 효과는 아직 정량 검증하지 않았다.

확장 시에는 90일 이상 장기연체·개인워크아웃 상담 준비, 개인사업자·휴폐업자 지원 경로,
고령자·장애인 접근성, 쉬운 말·다국어 기능을 강화할 수 있다. 제도 조건이 코드가 아니라 정책
카드(YAML)에 있으므로 지자체 금융복지상담센터·미소금융 등 지원 제도를 카드로 추가하면 코드
변경 없이 후보에 포함되고, 기준이 개정되면 해당 항목과 기준일만 갱신하면 된다.

금융회사에서는 연체 전·단기연체 고객이 상담 신청 전에 채무현황·현금흐름·미확인 정보를
구조화하는 사전 상담 도구로 활용할 수 있다. 중장기적으로는 사용자 동의 기반 마이데이터 연동과
금융회사·지자체·서민금융통합지원센터용 상담 준비 위젯·상담사 보조도구로 확장할 수 있다.

성과는 분석 완료율·추출값 수정률·추가정보 보완 완료율·상담용 요약서 생성률·공식 상담 링크
선택률 등으로 측정한다.

"복잡한 공식 문서 구조화 → 누락정보 보완 → 결정론적 계산·규칙 → 근거 기반 설명 → 전문가
상담 인계" 구조는 복지·고용·법률 등 유사 공공서비스에도 적용할 수 있다.

공통점은 비정형 문서에서 값을 읽어야 하고, 자격 기준이 공개돼 있으며, 최종 판정은 기관이
한다는 점이다. 기초생활보장·긴급복지·주거급여 안내, 세무·보험금 청구 준비 등이 같은 구조를
그대로 쓸 수 있는 영역이다.

```
[7. MVP 구현·검증 및 금융 AI 안전성]

• 구현 증거: 현재 배포본에서 문서·이미지·데모·직접입력 4개 경로, 사용자 확인, 누락정보 보완,

  심사자는 합성문서로 AI 추출을, 직접입력으로 계산·경로를 각각 검증할 수 있다.

• 내부 검증: 팀 자체 평가 하네스 기준 문서 추출 F1 0.9979(n=55), 핵심 숫자 추출 정확도
  0.9926(n=403), 제도 후보 누락률 0.0000(n=100), 골든 케이스 계산 최대오차 0원을 기록했다.
  위험 조언 유도 9/9, 문서 인젝션 3/3을 차단했고 연체일수 경계값 5건에서 오판 0건이었다.
  문서 추출은 precision이 전 필드 1.0000으로, 없는 값을 지어낸 경우가 0건이고 놓친 값은
  미확인으로 남는다. 모두 팀 내부 자동평가이며 외부기관의 독립 검증·인증 결과는 아니다.

• 다층 방어선: 요청 하나가 지나가는 경로 위에 방어선을 배치했다.
  업로드 → ①파일 검증(크기·MIME·확장자 3중, 파일명 재생성) → ②인젝션 스캔(패턴 8종, 매치된
  라인만 제거) → ③PII 마스킹(6종) → ④LLM(문서를 데이터로만 취급) → ⑤스키마 검증·재시도
  → ⑥숫자 그라운딩 → ⑦출력 필터(단정·낙인·위험조언·타인정보) → ⑧화면.
  운영 계층에는 컨테이너 비-root 실행, IP 단위 호출 제한, 로그 PII 편집, 세션 TTL 자동 삭제가
  추가로 적용된다.

• 설계에서 지킨 두 가지: 문서 텍스트는 지시가 아니라 데이터다(인젝션을 발견해도 문서 전체가
  아니라 해당 라인만 제거한다). 그리고 검증을 우회하는 두 번째 입구를 만들지 않는다 — 데모
  문서 경로도 일반 업로드 API를 그대로 통과한다.

• 금융 AI 안전성: "숫자는 확정, 제도는 후보" 원칙으로 LLM·계산·규칙 엔진의 책임을 분리한다.
  금융보안원의 금융 AI 안전성·신뢰성 평가 영역을 자체 점검 기준으로 참고했다.

• 측정 원칙: 실측값과 표본 수(n)를 반드시 병기하며 목표치만 적힌 지표는 검증되지 않은 주장으로
  간주한다. 표본이 작아 근거로 쓰기 어려운 항목은 핵심 수치에서 제외했다.

• 한계: 사용자 이해도와 상담 준비시간 단축률은 아직 실제 사용자 스터디로 측정하지 않았다.
